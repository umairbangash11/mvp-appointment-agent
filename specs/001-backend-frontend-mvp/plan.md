# Implementation Plan: Phase 1 MVP — Doctor Appointment Booking System

**Branch**: `001-backend-frontend-mvp` | **Date**: 2026-07-25 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-backend-frontend-mvp/spec.md`

## Summary

Build a full-stack appointment booking system for US doctors. The backend exposes a FastAPI + PostgreSQL
API handling doctor authentication (JWT + bcrypt), an SMS booking agent (Twilio + Groq llama-3.3-70b),
a voice call agent (Twilio Voice + Groq), SendGrid email confirmations, and a REST appointments API.
A minimal Next.js 14 frontend (Tailwind + Shadcn UI) is delivered alongside the backend so all APIs
can be verified end-to-end through a browser without external tooling.

## Technical Context

**Language/Version**: Python 3.11 (backend), TypeScript / Node.js 20 (frontend)
**Primary Dependencies**: FastAPI, SQLAlchemy 2.x, Alembic, python-jose, passlib[bcrypt], groq, twilio, sendgrid, APScheduler, pydantic-settings (backend); Next.js 14, Tailwind CSS 3, Shadcn UI, Axios (frontend)
**Storage**: PostgreSQL 15
**Testing**: pytest + httpx (backend integration tests); manual browser happy-path (frontend MVP)
**Target Platform**: Linux server (backend API), Browser — Chrome/Firefox/Safari (frontend)
**Project Type**: web (backend + frontend)
**Performance Goals**: p95 API response < 500ms; email/SMS delivery within 2 minutes of booking
**Constraints**: HIPAA-compliant encrypted storage; JWT 15-min expiry; US-region servers; no PHI in SMS or logs
**Scale/Scope**: MVP — single clinic, target ~100 appointments/day; single-doctor model for Phase 1

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked after Phase 1 design.*

| Principle | Status | Evidence |
|-----------|--------|---------|
| I. HIPAA Compliance & Patient Privacy | ✅ PASS | PHI fields encrypted at rest (SQLAlchemy + PostgreSQL); no PHI in SMS bodies (only reference ID + date + clinic name); AI disclosure enforced in every agent prompt; audit logs via `created_at/updated_at` on all PHI tables |
| II. AI Transparency & Ethical Boundaries | ✅ PASS | Every SMS/Voice agent system prompt starts with required disclosure; `SAFE_BOOKING_ONLY` guardrail rejects medical-advice requests and redirects |
| III. Phase-Gated Delivery | ⚠️ DEVIATION (justified — see Complexity Tracking) | Frontend is a minimal test harness; backend exit criteria must pass before frontend is marked done |
| IV. Secure Authentication & Session Management | ✅ PASS | JWT (python-jose) access token 15 min + refresh token 7 days; bcrypt via passlib; auto-logout enforced on frontend via inactivity timer; `doctor` role on all protected routes |
| V. Test-Before-Advance Gate | ✅ PASS | Backend happy-path integration tests (pytest) required before frontend verification; checklist in constitution Phase 1 exit criteria drives the gate |
| VI. Data Minimization & Channel Scope | ✅ PASS | Exactly 3 channels (SMS/Voice/Email); Groq `llama-3.3-70b`; no RAG, pgvector, Stripe, or extra channels |

**Structure Decision**: Web application (Option 2). Backend and frontend are co-located at repository
root. `backend/` contains all Python API code; `frontend/` contains the Next.js app. They communicate
over HTTP (`NEXT_PUBLIC_API_URL` env var). Shared nothing — no monorepo tooling required for MVP.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|--------------------------------------|
| Phase-Gated Delivery deviation: frontend scaffolded alongside backend | User explicitly requires end-to-end browser testing as the verification mechanism for Phase 1 backend APIs; without the frontend, manual Postman testing would be required for every endpoint. Frontend acts as the Phase 1 test harness, not a standalone Phase 2 feature. | Deferring frontend to strict Phase 2 means backend cannot be visually verified by non-technical stakeholders; user's explicit exit criterion requires browser-based validation. Constitution still satisfied: frontend is only marked COMPLETE after all backend exit criteria pass. |
