# US Doctor Appointment Booking Agent Constitution

## Core Principles

### I. HIPAA Compliance & Patient Privacy (NON-NEGOTIABLE)

Every feature, endpoint, agent response, and data flow MUST comply with HIPAA regulations:
- AI agents MUST disclose they are AI on every call/SMS (e.g., "I am an AI assistant.").
- Patient consent MUST be obtained before any data is collected.
- No PHI (Protected Health Information) MUST be transmitted in plain SMS content.
- No diagnosis, medical advice, or clinical recommendations MUST be generated by any AI agent.
- All patient data MUST be stored encrypted at rest on US-region servers only.
- Audit logs MUST be maintained for all PHI access and mutations.

**Rationale**: Legal obligation under HIPAA; violation carries civil and criminal penalties and terminates
the product's operating legitimacy.

### II. AI Transparency & Ethical Boundaries

- Every AI interaction (SMS, Voice) MUST begin with an explicit disclosure:
  "I am an AI assistant helping schedule your appointment."
- AI agents MUST NOT simulate human identity, provide medical advice, or generate diagnoses.
- Patients MUST be informed they are communicating with an AI before any data collection begins.
- No AI-generated content MUST be framed in a way that could be mistaken for clinical guidance.

**Rationale**: Trust, legal compliance, and ethical patient care require unambiguous AI disclosure at
every touchpoint.

### III. Phase-Gated Delivery (NON-NEGOTIABLE)

- Development MUST proceed one phase at a time: Phase 1 (Backend) before Phase 2 (Frontend).
- Phase 2 work MUST NOT begin until all Phase 1 exit criteria are fully met and tested.
- Exit criteria are defined in the Development Workflow section and MUST be validated before advancing.
- Parallelizing phase work or skipping phases is explicitly prohibited.

**Rationale**: Prevents integration failures; each layer must be independently testable and verified
before the next layer is built on top of it.

### IV. Secure Authentication & Session Management

- All doctor-facing routes MUST be protected by JWT authentication (python-jose).
- Passwords MUST be hashed using bcrypt; plain passwords MUST NEVER be stored, logged, or transmitted.
- JWT sessions MUST expire after 15 minutes of inactivity; auto-logout MUST be enforced on both
  backend and frontend.
- A token refresh mechanism MUST be implemented for active sessions.
- Role-based access: only the `doctor` role MUST be permitted to access dashboard and appointment routes.

**Rationale**: Protects sensitive patient appointment data. bcrypt + JWT is the project's agreed
authentication contract. [[principle-hipaa]]

### V. Test-Before-Advance Gate

- All Phase 1 exit criteria MUST be tested and pass before Phase 2 begins.
- Every API endpoint MUST have at least one integration test covering the happy path.
- AI agent flows (SMS, Voice) MUST be end-to-end tested before Phase 1 is marked complete.
- Frontend pages MUST be functionally verified (happy path + JWT guard) before Phase 2 is marked done.

**Rationale**: Prevents defect accumulation across phases; catching errors early reduces the cost of
fixing integrated systems.

### VI. Data Minimization & Channel Scope

- The system operates on exactly three channels: SMS (Twilio), Voice (Twilio), and Email (SendGrid).
- No additional channels (WhatsApp, Facebook, Instagram) MUST be introduced without explicit user approval.
- SMS content MUST NOT include PHI; only appointment reference IDs, dates, and clinic name are permitted.
- Email confirmation uses a single basic SendGrid template only; multi-template flows are out of MVP scope.
- The Groq API model `llama-3.3-70b` is the designated AI model for SMS and Voice agents.
- RAG/pgvector, Stripe payments, Brave Search, and daily-report cron MUST NOT be introduced in MVP scope.

**Rationale**: Scope discipline prevents MVP bloat; channel minimization limits attack surface and
reduces HIPAA compliance complexity.

## HIPAA Compliance & Security Requirements

### Data Handling Rules

- PHI fields (patient name, phone, insurance info, appointment details) MUST be stored in PostgreSQL
  with encryption at rest.
- No PHI MUST appear in application logs, SMS message bodies, voice transcripts, or error responses.
- All database connections MUST use SSL/TLS.
- All secrets (API keys, DB credentials, JWT secret key) MUST reside in `.env` files and MUST NEVER
  be hardcoded in source code.
- `.env` MUST be listed in `.gitignore`; `.env.example` with redacted values MUST be committed.

### Insurance Verification

- Insurance information is patient-reported (self-declared during booking); no real-time insurance
  API integration is in MVP scope.
- Insurance data MUST be stored encrypted and treated as PHI.

### Consent Flow

Before collecting any patient information via SMS or Voice, the AI agent MUST:
1. Identify itself as an AI.
2. State the purpose of data collection (appointment scheduling only).
3. Receive explicit verbal or text confirmation of consent before proceeding.

## Development Workflow & Phase Gates

### Phase 1 — Backend (Active Phase)

**Folder**: `backend/`

**Exit Criteria** (ALL must pass before Phase 2 begins):
- [ ] Doctor signup, email verification, login, logout, forgot-password, reset-password endpoints working
- [ ] JWT protects all dashboard and appointment routes; auto-logout enforced at 15 min
- [ ] SMS booking agent: receives Twilio webhook, runs Groq AI conversation, collects patient info,
      verifies insurance (self-reported), selects slot, books appointment, sends confirmation SMS
- [ ] Voice call agent: receives Twilio Voice webhook, runs Groq AI conversation, answers static FAQ,
      books appointment via voice, sends SMS confirmation after call
- [ ] SendGrid email: booking confirmation, appointment reminder, and doctor notification emails sent
- [ ] Insurance info collected and stored encrypted during booking flow
- [ ] Appointments API operational: `GET /appointments`, `GET /appointments/{id}`,
      `PUT /appointments/{id}`, `GET /dashboard/stats`
- [ ] All exit criteria manually tested and passing

### Phase 2 — Frontend (Locked Until Phase 1 Complete)

**Folder**: `frontend/`

**Exit Criteria** (ALL must pass before Phase 2 is marked done):
- [ ] Login page functional: JWT stored on success, redirect to dashboard, "Forgot password" link works
- [ ] Signup page: doctor registration form, email verification flow, success redirect
- [ ] Forgot password page: email input, reset link sent via SendGrid
- [ ] Dashboard: JWT-protected, auto-logout after 15 min inactivity, real appointment data displayed,
      stats cards (today count, total patients, recent bookings)
- [ ] Appointments page: full list, filter by date/status, patient details, cancel/reschedule option
- [ ] All pages tested on mobile and desktop (responsive); Shadcn UI + Tailwind medical blue theme

### Coding Standards

- No secrets hardcoded; always use `.env` loaded via `config/settings.py`.
- Smallest viable diff per task; no unrelated refactors.
- Every AI agent response MUST include AI disclosure language at the start.
- Error responses MUST NOT expose PHI or internal system stack traces.
- All route handlers MUST validate inputs at the boundary (Pydantic models).
